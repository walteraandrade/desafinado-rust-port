# Feature parity with the Electron build

Every feature of `desafinado`'s Electron build (as of `b269c9c`, 2026-11-14) and its state in the native build. Done means it works the same from the writer's side; motion is matched where GPUI allows and noted where not.

## Document and files
- [x] New (`Ctrl+N`), Open… (`Ctrl+O`), Save (`Ctrl+S`), Save as… (`Ctrl+Shift+S`), asking Save / Discard / Cancel over unsaved text (the dialogs are the GPUI file pickers, or `DESAFINADO_DEV_PICK_FILE`; the leave dialog is a GPUI dialog with Cancel, Discard and Save, focused on open, `Tab` `Shift+Tab` move between them, `Enter` or `Space` chooses and `Esc` cancels, with a 2px accent border as the focus ring)
- [x] Atomic save keeping mode and symlinks; conflict when the disk changed since the last read (External change notice: Reload from disk / Keep mine)
- [x] Unsaved text kept per file across restarts and a killed process; the last file reopens at start (the last file is kept in `last-file.txt` in the user data dir instead of `localStorage`)
- [x] Beyond Electron: each file keeps its place. Closing the app, or opening another file, and coming back puts the caret, the selection and the scroll where they were, with the Suggestions that were ready for review (with every refined version), the Notes, their General notes and the Review mode chip. A Suggestion still waiting for the model, or one that failed, is not kept. When the file changed outside the app in the meantime, the place follows the change line by line: a Suggestion over a changed line is dropped (a toast counts them, unless the open already shows one, such as restored unsaved changes), and a Note over one turns grey. Places live in `history.sqlite` (table `places`, added without a schema bump so older builds still open the file); they are written when the window closes, when another file or a New document opens, and before a reload from disk (which keeps the place too), not on a killed process
- [x] First Markdown argument on the command line opens; one instance per user data dir hands later files to the running app (an `flock` on `instance.lock` and a Unix socket `instance.sock` in the user data dir stand in for `requestSingleInstanceLock`)
- [x] Watcher: an external edit of the clean open file reloads and records an External Version; a dirty one shows the notice
- [x] Frontmatter: not a Block; frontmatter problems in the File menu; frontmatter panel to edit `name` and `description` (the panel sits above the editor instead of scrolling with the text; `Ctrl+Z` in a field undoes the field and writes that back as a new edit instead of undoing the Document; no screen-reader live region)

## Editor and Suggestions
- [x] Raw Markdown with light styling, Inter, 48rem column, headings bold (headings keep the body size and fenced or inline code stays in Inter, since the GPUI editor has one font size and family per buffer: ADR 0001; scrollbars always show, in the editor (where the text map stands in for it when the window has room), the Reading view, History, AI spend, Evals, the Library and Preferences; the Evals run dialog and its baseline list scroll without one)
- [x] Reading view (`Ctrl+Alt+R`, Edit → Reading view / Edit text, last in Edit): the Document rendered, without the frontmatter; links show their target on hover and never open (gpui-base `TextView`, so the rendered headings scale with the Document while the editor's do not; task checkboxes are drawn by `TextView` and are not interactive; code, fenced or inline, is in Noto Sans Mono (bundled), and a fenced block keeps its lines unwrapped and scrolls sideways with Shift+wheel or a sideways swipe, with no scrollbar and no language label; fenced code in a language the build knows (JSON and Markdown today, any letter case) is colored from the theme's roles: strings in success, numbers and literals in AI, keywords in accent, punctuation and comments in muted, rather than the editor's muted code colors; selectable text; anything that needs the editor, such as Review, Accept all or a toast's Show and Retry, leaves Reading view first, and so does opening History, Evals or AI spend; entering it closes the Ask bubble and a Refine field; the shortcut does nothing while a dialog, Preferences, the Review popover, the Ask bubble, a Refine field, the Library search or a frontmatter field is open or focused)
- [x] Bubble (`Ctrl+K`): Quick actions by typing, `↑` `↓` `Enter`, "Ask AI: …" free text (also shows on its own over a mouse or keyboard selection and hides while the pointer is down, as in Electron; `Esc` closes it and keeps it closed for that selection; it fades and rises in like Electron's and, beyond it, its Quick action rows enter one after another and it fades out on close, without the 0.98 scale and 3 px blur, which GPUI cannot do on a whole surface; the same holds for menus, the Review popover, Cards and the toast; a Card fades in again when it scrolls back into view, because the native build stops drawing Cards above the view; a hover Card waits 160 ms before it enters, as in Electron; reduced motion follows the desktop portal's setting, live, through gpui-base)
- [x] Target: selection or the Block under the cursor; Neighbors and title/section as context (the Target is previewed with the selection fill while the bubble is open)
- [x] Suggestion overlay: deleted text struck through, Replacement in the AI color, Changes counted, Rationale (a word-level Replacement shows in the line after the struck-through Original and a block-level one in rows opened under the range, on a patched gpui-base, ADR 0003; a line break inside a word-level Replacement shows as ↵ instead of breaking the line; the Card, in the left margin when the window is wide enough (the right is the text map's) and floating under the range otherwise, holds versions, Rationale, Changes and the actions; no shimmer or word-by-word reveal)
- [x] Card with Accept (`Ctrl+Enter`), Reject (`Esc`), Refine; Refine steps `‹ n / m ›` (`Ctrl+H` / `Ctrl+L`); `Alt+[` `Alt+]` between Suggestions; `Tab` into the Card (Reject is undoable with `Ctrl+Z` until the writer edits the text again, a stack standing in for the CodeMirror effect; `Ctrl+H` inside a Suggestion with one version does nothing instead of falling through to Find and replace; the focused Card button has a 2px accent border instead of an outline ring)
- [x] Native only: a text map right of the text, in place of the editor's scrollbar when the window has room for it (the Document in miniature, Suggestion rows in the AI color, the rows on screen on the fill; a click on a Suggestion goes there, a click elsewhere, a drag or the wheel scrolls) and a chip at the top and the foot of the text counting the Suggestions past that edge (`Alt+↑` / `Alt+↓` go to them); accepting or rejecting moves the caret on to the next Suggestion
- [x] Accept is an undoable edit; Discard when the writer edits inside a Suggestion or a newer one overlaps (Accept leaves the cursor at the end of the Replacement)
- [x] Beyond Electron: the editor stays free while the AI works. Each request runs on its own, and the requests tray in the editor's bottom right lists them with what was asked, where (Whole text, Selection, Paragraph, Refining) and the time so far, with Cancel (Stop for a Review); an answered request stays there for 8 seconds with Show, unless its Card is already open. The writer can type inside a running request's text: when the answer comes, the model's changes on lines the writer did not touch are kept and the rest left out, with the notice "Some changes left out: you edited those lines meanwhile" (only deleting all of the request's text drops it). A request whose range overlaps a newer one is still replaced by it
- [x] AI caret with flag and Instruction while a Refine or a Review pass runs ("Reviewing" during a Review pass; an Ask request shows in the requests tray instead, with no fill over its text; the flag flips left at the right edge; the bar breathes and the three dots pulse as in Electron, 4 px apart instead of 2 to stay on the 4 px grid; no caret glide)
- [x] Review pass with Focus (Edit → Review…), streamed one Suggestion at a time, Stop (Edit menu or the requests tray, which replaces the header's Reviewing chip); Accept all / Reject all (at most 6 Suggestions, one retry when the first answer is invalid and nothing validated yet; Accept all and Reject all act on review Suggestions only, and Accept all is one undoable edit; the first Suggestion is revealed when the pass ends if the editor is not focused)
- [x] Beyond Electron: Comment review. Edit → Review… without a Focus, or with a Focus that asks for an opinion, leaves Notes instead of Suggestions: General notes in a panel beside the text and numbered marks in the margin (at most 24 Notes, 15 shown before "Show more"); a Note opens on its mark with Suggest rewrite and Dismiss, and a Note whose text changed turns grey. Jev (`typesafe/jev-1.14`, OpenRouter Decisions API) reads a Focus and picks Comment or Revise; the header chip shows the choice and runs the Review again in the other mode. Notes are kept with the file's place (see Document and files), not in the file itself
- [x] Errors and retries shown as in the Electron build (toasts with Retry and Show actions for a failed Suggestion, Retry for a failed Review pass, notices for a partial pass, too-large Documents and no room; a failed Suggestion shows its error with Retry and Dismiss in rows opened under the range, as Electron's inline error widget; Show moves the cursor to the Suggestion)

## History
- [x] Versions with Cause (Started, Edited, Accepted, Opened, Restored, External, Saved mark) in `history.sqlite`, one History per file
- [x] Timeline under the header, a dot per Version (once they no longer fit, the newest stay as dots and the rest fold into a strip that jumps to any stretch; the Electron app always shows one dot per Version), compare with the current text, Restore (`←` `→` `Home` `End` step between dots while a Version or the full history is shown, not from a focused dot in the editing view; Now has no hover title)
- [x] Full history page "How this Document changed" (entry diffs are computed for every entry, not only near the viewport; the flash on a dot click ends without a fade)
- [x] Undo/redo keys (`Ctrl+Z`, `Ctrl+Shift+Z`, `Ctrl+Y`) (opening a file or Reload from disk starts a fresh undo stack, where CodeMirror kept it as one undoable change; Restore and a watcher reload are undoable as in Electron)

## Library and skills
- [x] Library rail (`Ctrl+B`), Library tree of roots, Skills, folders and files; keyboard tree navigation; descriptions; problems in the danger color (the rail buttons are icons with the label and shortcut in their tooltip, since GPUI has no vertical text; the Library slides in from the left as in Electron and, beyond it, slides back out on close; descriptions appear without the unfold motion; rows are one flat list, Tab does not step through the panel)
- [x] Library search (`Ctrl+P`) (no visually hidden result count, GPUI has no screen-reader layer)
- [x] Add a root, Refresh, New skill from template (Add uses the GPUI folder picker, or `DESAFINADO_DEV_PICK_FILE` like the Electron dev switch; New skill picks the folder from a list of rows instead of a dropdown)
- [x] Improve description (AI) (the proposal appears and leaves without the unfold motion)

## Evals
- [x] Evals page "How this Skill performs": last run, Did the Skill fire? / Did it help?, Each Eval table, suspicious cases (the Each Eval table is rows of flex cells; a flag's full wording is its tooltip, with no help cursor; inline `code` in the guide's sentences is plain text, the example blocks use Noto Sans Mono (bundled); Open report hands the file to `xdg-open`; the Evals icon breathes with GPUI's opacity animation)
- [x] Eval run through the Claude CLI with Arms, runs 1–5, Cancel, toast at the end, first-eval guide (Compare against is a list that unfolds under the field instead of a native select; Runs and Cost limit are text fields with the same checks, no spinner; `DESAFINADO_CLAUDE_CLI=<path>` names the CLI before PATH and `~/.local/bin`, a port addition for checks, with `scripts/fake-claude` as a stand-in that never calls the model; quitting during a run waits up to 6 s for it to stop, as in Electron)

## Preferences and themes
- [x] Preferences (`Ctrl+,`): themes (25 screen themes, Desafinado plus 24 after the book combinations, rebuilt for screen with heading, muted, success and danger roles, so they no longer match the Electron palettes, see [ADR 0002](adr/0002-screen-themes-with-color-hierarchy.md); Omarchy theme when present), Model, OpenRouter key, Quick actions (toggle, order, add, edit, delete) (beyond Electron, the panel slides in from the right and back out on close; the panel does not make the page behind it inert, as the modal `<dialog>` does; a theme applies at once without the view-transition crossfade; the choice is kept in `theme.txt` and the model in `model.txt` in the user data dir instead of `localStorage`; the Omarchy theme is read from `~/.local/state/omarchy/current` at start in every build, not only in dev, and is not followed live; the Quick actions list moves like Electron's (a new one fades in, ↑ ↓ glide the rows to their places, a deleted one shrinks away), and focus returns to the panel rather than to the neighboring control; the AI section has one more row, AI spend)
- [x] Version and commit at the bottom (the native crate version; `build.rs` reads the commit from `.git` like `config/build-info.ts`, `unknown` outside a checkout, `DESAFINADO_COMMIT` overrides it for packaging)

## AI and spend
- [x] OpenRouter called directly, through `HTTPS_PROXY` and `SSL_CERT_FILE` (oneCLI) (checked on the maintainer's machine; `SSL_CERT_FILE` adds to the bundled roots; `DESAFINADO_FAKE_AI=1` is a scripted local model for checks, a port addition)
- [x] Key screen and libsecret key store (the OpenRouter key dialog opens from the missing key banner and from Preferences, with the same states, plain-text offer and Remove key; a saved key reaches the next AI call without a restart; checked in Xvfb through the session and plain-text paths, since Xvfb has no Secret Service)
- [x] AI call records (task, models, provider, tokens, cost, latencies, finish reason, generation id) in `ai-calls.jsonl` (one record per attempt for a Suggestion, Refine, Review pass and Improve description, with the Electron task labels such as "cursor in p3 → Shorter", "refine p3 → warmer" and "review document → focus: …"; a failed or stopped call records its error kind; each record is written once, after the generation lookup, instead of being enriched in place; there is no `window.__aiCalls`)
- [x] Spend view: calls and total cost (the Electron build has no in-app view, only `ai-calls.jsonl` and `window.__aiCalls`; the native page, File → AI spend… or Preferences → AI spend, shows total US$, calls and priced calls, average per call, tokens, failed and retried calls, a 14-day chart, cost by model and by task, and the newest 50 calls, filtered by Today, 7 days, 30 days or All time; the page rises in and its bars grow from zero, 24 ms apart)

## Shell
- [x] Custom title bar with File and Edit menus and keyboard menu navigation (`↑` `↓` skip disabled items and wrap, `←` `→` switch menus, `Enter` or `Space` choose, `Esc` closes, `Tab` leaves; the menu buttons are not Tab stops in GPUI, so `Alt+F`, `Alt+E` and `F10` open a menu with its first item active, a port addition; `Esc` returns focus to where it was instead of to the menu button)
- [x] Toasts, missing key banner, start error screen (toasts take any number of actions, each a button that dismisses the toast; the start error screen shows when the user data folder cannot be created or written, the native counterpart of a failed platform kit)
- [x] Installs and runs locally (`cargo install --path crates/app` plus a desktop entry) (`./install.sh` installs the binary, a "Desafinado (native)" desktop entry for `text/markdown` with `%f`, and the icon under `~/.local/share`; `--uninstall` removes them; the window class is `desafinado-native` so it does not group with the Electron app)
